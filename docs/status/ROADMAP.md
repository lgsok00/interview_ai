## 배포 전 보완 작업 (2026-10-01)

기존 MVP 핵심 UI 구현·검증 완료와 별도로 실패 복구·이력서 안내와 일반 공개 기준 회원가입 UI를 완료했다 (2026-10-02).
다음은 내 계정 UI다. AI 요청 제한은 정책안 작성·운영값 확정 대기이며 구현·검증을 완료한 뒤 배포를 구체화한다.

1. **면접 질문 생성·답변 평가 재시도 UI — 구현·검증 완료**

      `POST /api/interview-sessions/{sessionId}/answers/{answerId}/evaluation/retry`를 연결했다. 기존 백엔드 정책은 유지한다.
    - 중복 클릭 잠금, 접수 후 질문 2초·평가 3초 상태 조회, 서버 오류 안내, 조회 실패 시 기존 결과 유지와 수동 새로고침을 제공한다. 미요청 답변의 최초 평가 요청도 연결했다.
    - 사용자 Vitest 10개 파일·104개 성공, lint 경고·오류 0, build 성공 및 브라우저 확인 완료 (2026-10-01). 신규 18개는 HTTP client·mock fetch 검증이다.
      component 상호작용과 최초 평가 요청은 신규 자동 테스트에 포함되지 않으며, 개별 브라우저 시나리오와 실제 AI 실패 유도 방식은 별도 전달되지 않았다.
    - 배포 전 통합 점검에서는 접수 후 성공 결과, 반복 클릭·한도, 타인 접근·상태 충돌·네트워크/AI 오류 복구를 확인한다.
2. **이력서 사용 가능 여부·오류 안내 — 구현·검증 완료 (2026-10-02)**
    - 신규 빈 추출은 `FAILED / TEXT_EXTRACTION_EMPTY`로 저장한다. 기존 `COMPLETED` 빈 본문도 API의 `usageStatus`로 사용 불가를 판정하고 문서/초안 화면에
      연결했다. DB migration·기존 데이터 일괄 변경은 없다.
    - 대표 미설정·추출 대기·추출 실패·텍스트 없음을 구분해 안내한다. 초안은 READY 선택·생성만 허용하고 조회 실패/중에는 차단하며, 이력서만 새로고침해 검토 내용을 유지한다. 대표 미설정 시 직접 선택도
      가능하다.
    - 서버의 본문·소유권 검증과 면접 대표 미설정 생략 정책을 유지한다. 사용 불가 원본 PDF도 보관·다운로드 가능하며 OCR은 후속 범위다.
    - 실제 정상·빈 페이지·공백·이미지 전용 PDF, 기존 null/빈/공백 완료 본문, 대표 미설정과 직접 선택 거부, 파일 교체·다운로드·RAG DELETE를 자동 검증했다. 백엔드 1,050개·Vitest
      115개 성공, lint 경고·오류 0, build 성공 및 사용자 브라우저 검토 완료를 확인했다.
    - 프런트엔드 신규 11개는 공통 사용 판정·안내 함수 테스트다. component 상호작용은 자동 검증하지 않으며 개별 수동 시나리오 결과는 별도 전달되지 않았다. 배포 전 통합 점검에서 실제 생성·상태

      브라우저 확인 완료를 확인했다.

4. **AI 요청 제한 — 정책안 작성, 확정 후 구현·검증**
    - 초기 권장값은 KST 하루 초기 질문 3회·꼬리 질문 15회·평가 30회·초안 3회, 사용자 대기·실행 합계 2건이다. 재시도 접수는 차감하고 자동 worker 재시도·기존 결과 반환은 차감하지 않는다.
    - 새 Flyway migration·MySQL 공통 사용량/예약 서비스를 실제 생성·재시도 트랜잭션에 연결한다. 동기 꼬리 질문의 실행 예약·worker 종료/lease 복구·재가입 우회·전역
      포화·embedding 통제를 포함한다.
    - 사용자 한도 429·전역 포화/저장소 장애 503·사용량 조회/안내를 구현한다. proxy 속도 제한과 실제 비용 관측은 배포 단계에서 구성한다. 상세 값·잠금·차감·구현 위치는 위 정책안을 따른다.
    - 정상 접수, 한도 직전/도달/초과·KST 자정·동시 요청·첫 행 생성·롤백·중복 호출·재시도·늦은 완료·저장소 장애와 한도 소진 뒤 답변/결과 유지 등을 검증한다. 코드는 아직 미구현이다.
5. **배포 환경 구체화와 배포 전 통합 흐름 점검**
    - 우선 보완과 공개 범위 결정을 진행한 뒤 도메인·HTTPS·인증 cookie/CORS/OAuth2 callback·DB/Qdrant·파일 영속 저장·AI worker·요청 제한 등 운영 구성을 정한다.
    - 로그인 → 문서 준비 → 면접 생성 → 답변 → 평가 → 결과, 초안 생성 → 검토 수정 → 적용 → 새 버전 확인, 질문/평가 실패 → 재시도 흐름을 점검한다. 기존 API wrapper 테스트와 별개로
      정상·실패 통합 결과를 기록한다.

관리자 사용자 관리 UI·RAG 운영 UI·실제 외부 수집 연결은 이번 배포 전 선행 개발 범위로 추가하지 않는다. STT/TTS·실시간 면접·PDF 리포트·자기소개서 PDF 업로드와 OCR은 후속 범위로 유지한다.

각 단계는 구현 코드와 관련 테스트가 모두 완료된 뒤 다음 단계로 이동한다. 구현만 끝난 경우에는 완료 처리하지 않고 `구현됨, 검증 대기`로 기록한다.
